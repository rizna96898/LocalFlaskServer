世界を選んでから、チャットを始め、発言するまでに、画面とサーバーが何をするか。

**この文書の位置づけ**: 2026-10-12 時点のコードから書き起こした下書き。
判断がつかなかった所には **【要確認 Q番号】** を付けている（番号は [`api.md`](api.md) からの通し）。
各APIの項目と返却は [`api.md`](api.md)、ファイルの形は [`data.md`](data.md)、作りかけは [`../status.md`](../status.md) を見る。

<a id="s1"></a>

## 登場するもの

<div align="right"><a href="#top">▲ 目次へ</a></div>

| | 役割 |
|---|---|
| 画面 | LLM_CHAT_CONSOLE。ブラウザで開く |
| APサーバー | `src/app.py`（ポート5000）。画面からの呼び出しを受ける |
| モデルサーバー | `src/server.py`（ポート5001）。モデルを読み込み、文章を生成する。APサーバーだけが呼ぶ |

モデルを使う処理（記憶の生成、返答）は、APサーバーがモデルサーバーへ送って結果を受け取る。
モデルサーバーが止まっていても、世界の選択やセッションの一覧・削除など、モデルを使わない操作はできる。

<a id="s2"></a>

## 全体の流れ

<div align="right"><a href="#top">▲ 目次へ</a></div>

```
世界を選ぶ ─→ 新規チャット ─→ 発言 ─→ 発言 ─→ …
               │                        ↑
               └ 裏で初期記憶を生成      既存のセッションを開いて続きから
```

<a id="s3"></a>

## 1. 世界を選ぶ

<div align="right"><a href="#top">▲ 目次へ</a></div>

1. 画面の「世界選択」を押すと、ブラウザに保存してある世界の一覧（`world_list`）が出る。
2. 世界を選ぶと `/world_start` を呼ぶ。サーバーは、その世界のセッション一覧を返す。
3. 画面は、選んだ世界（`selected_world_id`、`selected_world_name`）をブラウザに保存し、セッション一覧を表示する。
   それまで選んでいたセッションは未選択に戻す。

サーバー側には「今どの世界を選んでいるか」という状態は無い。覚えているのは画面（ブラウザ）だけ。

<a id="s4"></a>

## 2. 新規チャット

<div align="right"><a href="#top">▲ 目次へ</a></div>

画面の「新規チャット」1回で、APIを2つ続けて呼ぶ。

<a id="s4-1"></a>

### 2-1. セッションを作る（`/chat_startup`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

元データをセッションフォルダへコピーする。モデルは使わないので、すぐ終わる。

- 世界設定、登場人物の設定、キャラクターの画像をコピーする（詳細は [`api.md`](api.md)）。
- セッション一覧に1件足す。
- 画面は、返ってきたセッションIDを「選択中のセッション」としてブラウザに保存する。

<a id="s4-2"></a>

### 2-2. チャットを始める（`/new_chat`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

1. 進行状態のファイル（`prepare_status.yaml`）を作る。
2. **初期記憶の生成を裏で始める**（下の「3. 初期記憶の生成」）。
3. 世界設定の `開始メッセージ` を履歴に書き、画面に返す。

裏の生成が終わるのは待たない。画面にはすぐ開始メッセージが出るが、その時点では記憶はまだできていない。

- **【要確認 Q29】** 初期記憶ができる前に発言できてしまう。記憶ができるまで発言を待たせる（または画面で「準備中」と出す）べきか。
  進行状態のファイルはそのための仕組みに見えるが、今は発言の前に確かめていない。

<a id="s5"></a>

## 3. 初期記憶の生成（裏の処理）

<div align="right"><a href="#top">▲ 目次へ</a></div>

`/new_chat` が始め、別のスレッドで進む。モデルを何度も呼ぶので、時間がかかる。

<a id="s5-1"></a>

### 3-1. 世界の記憶

<div align="right"><a href="#top">▲ 目次へ</a></div>

- 材料: 世界設定の `登場人物`、`シナリオ本文` の `現在`、`開始メッセージ`
- モデルに1回送り、返ってきたYAMLを整えて `world_memory.yaml` に保存する。
- 返事が期待の形（`現在の状態` と `世界の状態` を持つ）でなければ、もう1回だけ送り直す。
- `世界の状態` → `参加者` が空なら失敗とする。

<a id="s5-2"></a>

### 3-2. キャラクターの記憶

<div align="right"><a href="#top">▲ 目次へ</a></div>

世界の登場人物のうち、`参照種別` が `character` の人物を、1人ずつ順に処理する。1人につきモデルを7種類の用途で呼ぶ。

| 順 | 段階 | やること | 結果の使い道 |
|---|---|---|---|
| 1 | 要約 | キャラクター設定・シナリオ・開始メッセージから、今の状況を箇条書きにする | 以降の段階の材料。`temp/` に保存 |
| 2 | 場所 | 要約から、今いる場所を決める | `場所` |
| 3 | 分類 | 要約の各行を「行動」「状態」「心情」に分ける | `行動`、`状態`、`心情`。`temp/` に保存 |
| 4 | 服装 | キャラクター設定から、今の服装を決める | `服装` |
| 5 | 所持品 | 服装・場所・要約から、持ち物を決める | `所持品` |
| 6 | 意識 | 開始メッセージから、今意識を向けている相手を決める | `意識` |
| 7 | 金額 | 所持金を決める | `金額` |

全部そろったら `character/{ID}_memory.yaml` に保存する。`関係性` には、世界の記憶の `現在の状態` → `参加者` をそのまま入れる。

- どれか1つの段階で失敗すると、そのキャラクターの記憶は保存されず、**残りのキャラクターも処理しない**。
- 各段階で使うプロンプトと生成の設定は [`prompts.md`](prompts.md)。
- **【要確認 Q30】** 途中で失敗したとき、やり直す手段が無い（新規チャットを作り直すしかない）。失敗した段階からやり直せるべきか。
- **【要確認 Q31】** 登場人物が複数いる場合、1人ずつ順番に処理する。1人あたりモデルを7回以上呼ぶので、人数に比例して時間がかかる。

<a id="s6"></a>

## 4. 進行状態（`prepare_status.yaml`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

裏の処理がどこまで進んだかを、セッションごとに記録する。

| 項目 | 値 | 意味 |
|---|---|---|
| `status` | `processing` | 処理中 |
| | `ready` | 終わって、次へ進める |
| | `error` | 失敗した |
| `complete_stage` | `new_chat`／`prepare`／`main_chat`／`mob_chat`／`after` | どの段階の話か |
| `error_stage` | `world`／`character` など | 失敗した場所 |
| `error_message` | | 失敗の内容 |
| `needs_mob_chat`、`mob_count`、`next_speakers` | | 複数キャラクターの会話用（未使用） |

`complete_stage` の並びは、1回の発言を「前処理 → 本処理 → モブの発言 → 後処理」に分けて順に進める設計を表している。

| 値 | 段階 |
|---|---|
| `new_chat` | 新規チャット（初期記憶の生成） |
| `prepare` | 発言の前処理 |
| `main_chat` | 返答の生成 |
| `mob_chat` | 他のキャラクターの発言 |
| `after` | 発言の後処理（記憶の更新など） |

今のコードが実際に書き込むのは次のとおり。

| 時点 | `status` | `complete_stage` |
|---|---|---|
| `/new_chat` を受けた直後 | `processing` | `new_chat` |
| 世界の記憶ができた | `ready` | `new_chat` |
| 世界・キャラクターの記憶で失敗 | `error` | `new_chat`（`error_stage` に `world` か `character`） |
| `/chat` を受けた直後 | `processing` | `main_chat` |
| 返答ができた | `ready` | `main_chat` |

- **【要確認 Q32】** `ready` / `new_chat` になるのは「世界の記憶ができた時点」で、キャラクターの記憶はまだ生成中。
  キャラクターの記憶が全部できても、状態は変わらない。「初期記憶がすべてできた」ことを表す状態が無い。
- **【要確認 Q33】** 世界の記憶で失敗して `error` を書いた直後に、続く処理が `ready` で上書きしてから、もう一度 `error` を書いている
  （最終的には `error` になるが、`error_stage` は `character` になり、本当の原因の `world` が消える）。
- **【要確認 Q34】** 状態を**読んで待つ**側の処理は、今は無い（前処理・後処理と一緒に削除した）。
  画面から状態を問い合わせるAPIも無い。画面に進み具合を出す予定はあるか。

<a id="s7"></a>

## 5. 発言する（`/chat`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

1. 画面は、入力欄の内容を自分の吹き出しとしてチャット欄に足し、選択中のセッションIDと一緒に送る。送信中は「発言」ボタンを押せなくする。
2. サーバーは、進行状態を `processing` / `main_chat` にする。
3. 返答を作る（作りかけ。[`../status.md`](../status.md)）。
4. 進行状態を `ready` / `main_chat` にする。
5. プレイヤーの発言と返答を、この順で履歴に足して保存する。
6. 画面は、返ってきた返答を吹き出しとして足す。

- 返答の生成に失敗した場合、履歴には何も足さない。画面にはエラーが出る。
- **【要確認 Q35】** 返答の生成に失敗したとき、画面には自分の発言の吹き出しが残るが、履歴には入っていない。
  セッションを開き直すと、その発言は消える。失敗した発言は画面からも消す（または入力欄に戻す）べきか。

<a id="s7-1"></a>

### 本来の形として想定されているもの

<div align="right"><a href="#top">▲ 目次へ</a></div>

進行状態の `complete_stage` と、`files/prompts/chat/` のフォルダ分けから読み取れる設計は、次のとおり。
今は「本処理」の一部しか無い。

| 段階 | やること（プロンプトYAMLの名前から） |
|---|---|
| 前処理（`01_preprocess/`） | 世界の記憶の更新、誰の発言かの判定 |
| 本処理（`02_main/`） | 返答の検証、返答の生成、誰に向けた発言かの判定 |
| 後処理（`03_postprocess/`） | パラメーターの変動、要約の更新、世界の記憶の更新、キャラクターの所持品と記憶の更新 |

- **【要確認 Q36】** 上の表は、ファイル名からの推測。各段階で本来やりたいことと、その順番。

## 6. 再送する（`/re_chat`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

画面の「再送」を押すと、チャット欄にある**自分の最後の発言**の文章を取り出し、もう一度自分の吹き出しとして足したうえで、`/re_chat` に送る。

サーバー側は作りかけ（[`../status.md`](../status.md)）。本来の動きは未確認（[`api.md`](api.md) の Q16）。

<a id="s9"></a>

## 7. 既存のセッションを開く

<div align="right"><a href="#top">▲ 目次へ</a></div>

1. 画面でセッション一覧の行を押すと、そのセッションを「選択中」としてブラウザに保存し、`/selected_session` を呼ぶ。
2. サーバーは履歴を返す。古い分は10件ごとに畳んで「印」にする（[`api.md`](api.md)）。
3. 画面は、印をクリックされたら `/selected_message` でその10件を取り寄せ、印と置き換える。

以後の発言は、そのセッションに足されていく。

<a id="s10"></a>

## 8. チャット画面の画像

<div align="right"><a href="#top">▲ 目次へ</a></div>

- アイコン: 吹き出しを作るたびに、`/session_image/{セッションID}/icon/{発言者のID}` から読む。無ければ名前の頭文字を出す。
- 立ち絵: 吹き出しかアイコンをクリックすると、その発言者の立ち絵を `/session_image/{セッションID}/standing/{発言者のID}` から読んで、中央の欄に出す。
  無ければ欄を初期表示に戻す。
- どちらも、新規チャット時にセッションへ退避した画像。プレイヤーとシステムのメッセージには画像が無い。
- **【要確認 Q37】** 立ち絵は「クリックしたら出る」。新しい返答が来たときに、その発言者の立ち絵へ自動で切り替えるのが本来の形か
  （欄の名前は「発言キャラクター立ち絵」）。

<a id="s11"></a>

## 9. セッションを削除する

<div align="right"><a href="#top">▲ 目次へ</a></div>

セッション一覧でチェックを付けて「選択削除」を押すと、`/delete_session` を呼ぶ。
サーバーは、一覧から外し、セッションフォルダごと消す。開いていたセッションが消えた場合、画面はチャット欄を空に戻す。
